# Data dictionary

Licence: CC BY 4.0 (see `LICENSE-data`).

```
data/
├── raw/<session_id>.csv     one row per sample, exactly as the ESP32 printed it
├── raw/<session_id>.json    the session's metadata ("sidecar")
├── processed/               generated by the analysis scripts (not committed)
│   ├── truth/<session_id>_truth.csv
│   ├── estimates/<condition>/<session_id>.csv
│   └── models/gru_<condition>.pt
└── splits.json              which sessions are train / validation / test
```

Raw files are never edited. `logger.py` refuses to overwrite one.

Session IDs are `<block>_<YYYYMMDD>_<HHMMSS>` (local time when recording
started), e.g. `C_20261015_143002`. The block letters are explained in
SPEC.md section 5.

## Raw CSV columns

| Column | Unit | Meaning |
|---|---|---|
| `t_us` | µs | ESP32 time since boot when the row was made |
| `seq` | - | row number since the last `reset`; a gap means a row was lost on the USB link |
| `raw_mm` | mm | what the VL53L0X returned; `-1` = no reading this time |
| `clean_mm` | mm | the reading if the sensor guard accepted it, else `-1`. Not changed by the injector |
| `faulted_mm` | mm | what the estimators received: `clean_mm` after the fault injector (3 decimals); `-1` = no reading |
| `ge_state` | 0/1 | injector state: 1 = BAD (inside a burst). Always 0 when injection is off |
| `mode` | text | `variance`, `frozen`, `bias`, `randbias`, `sysbias`, `blend`, or `off` when injection is off |
| `button` | 0/1 | 1 while the button is held (physical fault present, Block E) |
| `recovery_event` | code | most important sensor event since the previous row (table below) |
| `kf_pos`, `kf_vel` | m, m/s | Kalman filter estimate (`nan` until the first reading) |
| `gated_pos`, `gated_vel` | m, m/s | innovation-gated Kalman filter |
| `imm_pos`, `imm_vel` | m, m/s | IMM estimate |
| `imm_p_bad` | 0-1 | IMM probability of the "bad readings" mode |
| `kf_us`, `gated_us`, `imm_us` | µs | time each estimator's update took on the ESP32 |

Positions are in **metres** (the estimators' unit), distances in **mm**
(the sensor's unit): `kf_pos` ≈ `faulted_mm / 1000`.

### `recovery_event` codes

The same numbers in both firmware builds (they are the Spec 2 guard's
`EventType`):

| Code | Meaning | Build |
|---|---|---|
| 0 | nothing | both |
| 1 | latch-up trip: power removed | guard (Block G) |
| 2 | latch-up lockout: power stays off | guard |
| 3 | sensor fault: an outage starts | both |
| 4 | one reset / recovery step was tried | both |
| 5 | sensor recovered: this row is the first good reading again | both |
| 6 | recovery failed (keeps retrying in the standard build) | both |
| 7 | the guard's current sensor stopped answering | guard |

Every event is also printed in full on a `#` line, which the logger stores
in the sidecar (`events`).

## JSON sidecar

| Key | Meaning |
|---|---|
| `session_id`, `block`, `block_name` | which session, which experiment block |
| `start_utc`, `duration_s` | when, how long |
| `synthetic` | `false` for real recordings; `true` only for the demo data |
| `user` | typed in by Vaishvi: `temp_c`, `string_length_m`, `rest_distance_mm`, `amplitude_mm`, `card_size_cm`, `target_distance_mm` (Block A), `supply_v`, `notes` |
| `firmware` | every `key=value` from the firmware's `#` lines: commit (`fw_commit`), build, injector settings (`entry_far`, `entry_near`, `persist_far`, `persist_near` per 0.1 s, `r_ref_mm`, `d_src_mm`, `sample_period_s`, `sigma_nom_mm`, `kappa`, `bias_c_sigmas`, `randbias_sigmas`, `lambda`, `mode`, `seed`), estimator settings (`kf_q`, `gated_coast_s`, `imm_r_bad_factor`, ...), memory use (`kf_bytes`, ...) |
| `events` | every `# event` / `# guard_event` line, parsed |
| `firmware_lines` | every `#` line exactly as printed |
| `commands_sent` | the serial commands the logger sent before recording |
| `ge_parameters_file` | Block F: the Spec 2 file used |
| `counts` | `rows`, `lost_rows` |
| `logger_git_commit` | commit of this repository when the session was recorded |

## splits.json

`train`, `validation`, `test`: lists of session IDs (made by
`analysis/make_splits.py`; whole sessions, about 60/20/20 inside each block
B-G, append-only). Block A is not split. Tuning uses only `validation`, the
GRU trains only on `train`, and every reported number comes from `test`.

## Processed files

`truth/<id>_truth.csv`: `t_us`, `t_s`, `truth_m` (fitted position),
`truth_vel_m_s`, `window` (which fit window), `used_in_fit`, `resid_mm`
(reading minus fit), `rts_m` (the RTS smoother check).

`estimates/<condition>/<id>.csv`: per-sample truth, readings, BAD label,
regime (0 nominal, 1 burst, 2 recovery), `scored` (1 = counted in the
metrics), and each estimator's position and variance.
